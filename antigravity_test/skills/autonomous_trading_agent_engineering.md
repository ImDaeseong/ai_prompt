# Skill: Autonomous Trading Agent Engineering (자율 트레이딩 에이전트 엔지니어링)

> ID: SKILL-TRADE-ENG-001 | Version: 1.0 | Last Updated: 2026-09-25

> **이것은 금융·투자·세무 자문이 아니다.** 이 스킬은 "자율적으로 실제 자금을 다루는 소프트웨어 시스템을 어떻게 안전하게 설계하는가"라는 **엔지니어링 문제**만 다룬다. 어떤 전략·자산·시장에 투자해야 하는지는 다루지 않으며, 그런 판단은 하지 않는다. 과거 성과는 미래를 보장하지 않고, 자동화된 시스템도 원금 전액 손실 위험을 없애지 못한다. 실제 자금을 투입하기 전에는 반드시 자격을 갖춘 전문가와 상담한다.

이 스킬은 "AI 트레이딩 에이전트를 만드는 법" 류의 영상에서 반복되는 주장 — 정확한 데이터, 24시간 안정 운영, 명확한 목표, 행동을 바꾸는 피드백 루프 — 을 검증한 뒤, 이 저장소가 이미 다른 고위험 자동화(인증·결제·삭제 등)에 적용하는 것과 같은 규율로 일반화한 것이다. `계산기`(입력→출력, 기억 없음)와 `연구원`(가설→검증→학습)의 차이를 실제로 만드는 것은 프롬프트 문구가 아니라 아래 네 기둥과 자본 노출 단계다.

## 1. 네 기둥 — 어느 하나가 없으면 자동화된 계산기일 뿐이다

### 정확한 데이터 (Accurate Data)
- 데이터 소스의 지연·결측·이상치를 별도로 로깅한다. "값이 없음"과 "값이 0임"과 "수집 실패"를 같은 상태로 섞지 않는다.
- 데이터 출처가 바뀌거나 스키마가 바뀌면 조용히 계속 돌지 말고 실패로 멈춘다.

### 24시간 안정 운영 (24/7 Reliability)
- 프로세스 크래시, 네트워크 단절, API 레이트리밋에서 자동 재시작하되 **무한 재시도로 손실을 키우지 않는다** — 재시도 횟수/시간 상한과 킬 스위치가 항상 있어야 한다.
- 킬 스위치는 사람이 원격에서 즉시 개입해 모든 포지션을 정지·청산할 수 있는 경로여야 하며, 에이전트 자신이 그 경로를 비활성화할 권한을 가져서는 안 된다.

### 명확한 목표와 종료 조건 (Explicit Goals + Stop Conditions)
- "수익을 내라" 같은 목표는 목표가 아니다. 성공 조건, 실패 조건, 그리고 실패 조건에 도달했을 때의 **정지 행동**을 각각 명시한다.
- 이 저장소의 `[LOOP-START] goal / exit criteria / max iterations` 규율을 그대로 적용한다 — 전략 실험도 최대 반복·최대 손실·최대 기간 중 하나를 항상 선언하고 시작한다.

### 행동을 바꾸는 피드백 루프 (Feedback That Changes Behavior)
- 로그를 쌓기만 하고 전략 파라미터가 그대로면 피드백 루프가 아니다. 관찰 → 가설 → 변경 → 재관찰이 실제로 연결돼야 한다. 관찰이 행동으로 이어지지 않으면 장식일 뿐이다.
- 피드백은 반드시 사람이 검토 가능한 형태로 기록한다(무엇을 관찰했고, 어떤 가설을 세웠고, 무엇을 바꿨는지). "AI가 스스로 개선했다"는 문장은 증거가 아니다.

## 2. 과학적 방법 루프 (한 번에 변수 하나)

```
기준선 설정 (현재 전략, 현재 성과 지표 고정)
        ↓
가설 하나 수립 ("X를 바꾸면 Y가 개선될 것이다")
        ↓
변수 하나만 변경 (동시에 여러 변수를 바꾸면 원인을 특정할 수 없다)
        ↓
아웃오브샘플 데이터로 검증 (백테스트 데이터로 재검증 금지 — 과적합)
        ↓
개선되면 채택 + 회귀 가드, 개선 안 되면 원상복구 + 가설 폐기 기록
```

이 저장소의 검증 루프 규율(같은 방식이 두 번 실패하면 접근 변경, 세 번째 반복 전에 HOLD)을 그대로 적용한다. "이번엔 다를 것"이라는 근거 없는 반복은 손실을 키우는 가장 흔한 실패 모드다.

## 3. 자본 노출은 반드시 단계적이다

| 단계 | 조건 | 다음 단계로 가는 승인 |
|---|---|---|
| 백테스트 | 과거 데이터, 자금 없음 | 아웃오브샘플 성과가 기준선을 넘음 |
| 페이퍼 트레이딩 | 실시간 데이터, 가상 자금 | 실거래 조건(슬리피지·수수료·지연) 포함 후에도 성과 유지 |
| 소액 실거래 | 실제 자금, 손실 한도 낮게 고정 | 정해진 최소 기간·거래 횟수 동안 킬 스위치·로그·재시도 상한이 실제로 작동함을 관찰 |
| 확장 | 위 단계 통과 + **사람의 명시적 승인** | 확장 폭과 다음 재검토 시점을 다시 고정 |

각 단계 전환은 이 저장소의 고위험 작업 규율과 동일하게 **자동 통과시키지 않는다** — 인증·결제·삭제 작업처럼, 자동 검사가 전부 통과해도 사람 승인 없이 다음 단계로 넘어가지 않는다. 한 단계에서 다음 단계로 건너뛰는 것("바로 실거래로 시작")은 이 원칙을 어기는 것이다.

## 4. 감사 가능한 결정 기록

에이전트가 내린 모든 자율 결정(진입·청산·파라미터 변경)은 다음을 남겨야 한다: 시각, 입력 데이터 스냅샷 또는 해시, 판단 근거, 실행 여부, 실행 결과. 이는 "AI가 옳았다"는 증명이 아니라 사후에 어떤 컨텍스트에서 어떤 결정이 나왔는지 추적 가능하게 하는 장치다 — 이 저장소의 `review_change_ledger.py`/`record_hermes_run.py`가 코드 변경에 대해 하는 것과 같은 목적을, 트레이딩 결정을 위해 별도로 설계해야 한다(두 스크립트 자체가 트레이딩 필드를 지원하지는 않는다).

거래소·중개사의 API 이용약관과 자동매매 관련 규제는 관할·상품·중개사마다 다르며 이 스킬이 다루지 않는다. 실제 자금을 투입하기 전에 해당 거래소 약관과 소재 국가의 규제를 별도로 확인한다.

## 안티패턴

1. **킬 스위치가 에이전트 자신의 프로세스 안에만 있음** — 그 프로세스가 멈추면 킬 스위치도 같이 죽는다. 독립 경로가 필요하다.
2. **백테스트 데이터로만 가설을 검증하고 아웃오브샘플 없이 실거래 전환** — 과적합을 실거래 손실로 처음 발견하게 된다.
3. **동시에 여러 파라미터 변경 후 "성과가 좋아졌다"고 결론** — 무엇이 원인인지 알 수 없다.
4. **손실 한도 없이 "일단 소액으로 시작"** — 소액이어도 무한 손실 한도는 소액이 아니다.
5. **단계 전환에 사람 승인 없이 자동 스케일업** — 이 저장소 전체가 경계하는 "자동 검사 통과 = 출시 승인"의 금융판이다.
6. **결정 로그 없이 "학습했다"고만 서술** — 무엇을 관찰해 무엇을 바꿨는지 연결되지 않으면 학습이 아니다.

## 검증 체크리스트

- [ ] 데이터 결측/실패가 "0"이나 침묵이 아니라 별도 상태로 보고되는가.
- [ ] 킬 스위치가 에이전트 프로세스 외부에서 독립적으로 작동하는가.
- [ ] 각 실험이 목표·실패조건·정지행동·최대 반복(또는 손실·기간)을 선언하고 시작하는가.
- [ ] 한 번에 변수 하나만 바꾸고 아웃오브샘플로 검증하는가.
- [ ] 백테스트 → 페이퍼 → 소액 실거래 → 확장의 각 전환에 사람의 명시적 승인이 있는가.
- [ ] 모든 자율 결정이 시각·근거·결과와 함께 감사 가능한 형태로 기록되는가.
- [ ] 실제 자금 투입 전 "이것은 투자 자문이 아니며 전문가 상담이 필요하다"는 경계를 사용자에게 직접 다시 말했는가 — 스스로만 인지하고 넘어가지 않았는가.
- [ ] 대상 거래소·중개사의 자동매매 관련 이용약관과 소재 국가의 규제를 별도로 확인했는가.
